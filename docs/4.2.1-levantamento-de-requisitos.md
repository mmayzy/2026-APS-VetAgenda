# 4.2.1 Levantamento de Requisitos

## Como os requisitos foram levantados

Os requisitos do VetAgenda foram levantados a partir do problema e das necessidades descritas na seção 4.1, considerando o uso atual de WhatsApp e agenda de papel para organizar os atendimentos. O levantamento foi direcionado para os cadastros, os agendamentos, os cancelamentos, os reagendamentos e a consulta da agenda.

Como a cliente do projeto é fictícia, algumas informações foram definidas como decisões de projeto. Essas definições orientam o desenvolvimento do sistema, mas não representam confirmações realizadas por uma cliente real.

## Da fala à necessidade

| # | Fala ou pergunta | O que é | Necessidade por trás |
|---|---|---|---|
| F1 | "Atualmente, organizo os agendamentos e informações via WhatsApp e uma agenda de papel, porém dessa maneira podem gerar esquecimentos e é mais difícil de manter a organização." — Secretária | Necessidade | Centralizar as informações e os agendamentos em um único sistema, reduzindo esquecimentos e problemas de organização. |
| F2 | Quais informações devem ser obrigatórias no cadastro de tutores? | Decisão de projeto | Definir os dados necessários para cadastrar um tutor. Foram definidos como obrigatórios: nome completo, telefone, CPF e e-mail. |
| F3 | Quais informações devem ser obrigatórias no cadastro de animais? | Decisão de projeto | Definir os dados necessários para cadastrar um animal. Foram definidos como obrigatórios: nome, espécie, tutor responsável e raça. |
| F4 | Quais informações devem ser obrigatórias no cadastro de veterinários? | Decisão de projeto | Definir os dados necessários para cadastrar um veterinário. Foram definidos como obrigatórios: nome completo, CRMV, telefone, especialidade e e-mail. |
| F5 | Quais informações devem ser registradas ao agendar uma consulta? | Decisão de projeto | Definir os dados necessários para realizar um agendamento. Foram definidos como obrigatórios: animal, veterinário, data e horário. |
| F6 | Quando uma consulta for cancelada, o sistema deve registrar o motivo do cancelamento? | Decisão de projeto | Definir se o motivo do cancelamento será obrigatório. Foi decidido que o motivo poderá ser registrado, mas seu preenchimento será opcional. |
| F7 | Ao reagendar uma consulta, o sistema poderá permitir a troca do veterinário? | Decisão de projeto | Definir quais informações poderão ser alteradas durante um reagendamento. Foi decidido que será possível alterar o veterinário, a data e o horário da consulta. |
| F8 | O veterinário poderá consultar apenas sua própria agenda ou poderá consultar a agenda de todos os veterinários? | Decisão de projeto | Definir o acesso dos veterinários à agenda. Foi decidido que cada veterinário poderá consultar somente a própria agenda, enquanto a secretária poderá organizar os agendamentos da clínica. |
| F9 | Se já existir uma consulta para o mesmo veterinário no mesmo horário, o sistema deve impedir um novo agendamento? | Decisão de projeto | Evitar conflitos de horários na agenda. Foi definido que o sistema impedirá duas consultas para o mesmo veterinário na mesma data e no mesmo horário. |
| F10 | Qual é o tempo máximo aceitável para apresentar a consulta da agenda? | Decisão de projeto | Definir o tempo de resposta esperado para a consulta da agenda. Foi estabelecida como meta a apresentação da agenda em até cinco segundos. |

## Histórias de usuário

| # | História de usuário | Veio de |
|---|---|---|
| HU01 | Como **secretária**, quero **cadastrar tutores**, para **manter os dados dos clientes organizados em um único lugar**. | F1 |
| HU02 | Como **secretária**, quero **cadastrar animais**, para **manter os dados dos animais organizados e vinculados aos seus tutores**. | F1 |
| HU03 | Como **secretária**, quero **cadastrar veterinários**, para **ter os profissionais disponíveis para os agendamentos**. | F1 |
| HU04 | Como **secretária**, quero **organizar as consultas da clínica**, para **manter os atendimentos agendados, cancelados e reagendados sob controle**. | F1 |
| HU05 | Como **secretária ou veterinário**, quero **consultar a agenda**, para **visualizar os horários e os atendimentos marcados de acordo com meu acesso**. | F1 |

## Requisitos funcionais

| # | Nome | Requisito | Veio de |
|---|---|---|---|
| RF01 | Cadastrar tutor | O sistema deve permitir o cadastro de tutores, exigindo nome completo, telefone, CPF e e-mail. | HU01, F2 |
| RF02 | Cadastrar animal | O sistema deve permitir o cadastro de animais, exigindo nome, espécie, raça e tutor responsável. | HU02, F3 |
| RF03 | Cadastrar veterinário | O sistema deve permitir o cadastro de veterinários, exigindo nome completo, CRMV, telefone, especialidade e e-mail. | HU03, F4 |
| RF04 | Agendar consulta | O sistema deve permitir o agendamento de consultas, exigindo a seleção de um animal, um veterinário, uma data e um horário. | HU04, F5 |
| RF05 | Cancelar consulta | O sistema deve permitir o cancelamento de consultas agendadas, possibilitando o registro opcional do motivo do cancelamento. | HU04, F6 |
| RF06 | Reagendar consulta | O sistema deve permitir a alteração da data, do horário e do veterinário de uma consulta agendada. | HU04, F7 |
| RF07 | Consultar agenda | O sistema deve permitir que a secretária consulte a agenda da clínica e que cada veterinário consulte somente sua própria agenda. | HU05, F8 |
| RF08 | Impedir conflito de horário | O sistema deve impedir o agendamento de duas consultas para o mesmo veterinário na mesma data e no mesmo horário. | F9 |

## Requisitos não funcionais

| # | Categoria | Requisito | Veio de |
|---|---|---|---|
| RNF01 | Dispositivo | O sistema deve funcionar em navegador nos computadores da clínica, sem necessidade de instalação de um programa específico. | Decisão de projeto |
| RNF02 | Acesso | O sistema deve restringir as funções de cadastro e alteração dos agendamentos aos usuários autorizados. | Decisão de projeto |
| RNF03 | Desempenho | O sistema deve apresentar a consulta da agenda em até cinco segundos. | F10 |

## Conferência com a 4.1

| Item da 4.1 | Requisitos relacionados |
|---|---|
| O sistema cadastra tutores. | RF01 |
| O sistema cadastra animais. | RF02 |
| O sistema cadastra veterinários. | RF03 |
| O sistema agenda consultas. | RF04 |
| O sistema permite cancelar e reagendar consultas. | RF05 e RF06 |
| O sistema consulta a agenda de atendimentos. | RF07 |

O RF08 complementa o RF04, pois a verificação de disponibilidade do veterinário deve ocorrer durante a realização de um novo agendamento.

### Conferência das histórias e requisitos

**Toda história de usuário tem requisito?** Sim. A HU01 está relacionada ao RF01, a HU02 ao RF02, a HU03 ao RF03, a HU04 aos RF04, RF05 e RF06, e a HU05 ao RF07.

**Todo requisito funcional tem origem?** Sim. Os RF01 a RF07 vieram das histórias de usuário e o RF08 veio da necessidade de evitar conflitos de horários, identificada na decisão F9.

**Todo item do escopo da 4.1 aparece nos requisitos?** Sim. As funcionalidades de cadastro de tutores, animais e veterinários, agendamento, cancelamento, reagendamento e consulta da agenda estão contempladas nos RF01 a RF07.

**O que a conferência mostrou?** A conferência confirmou que as funcionalidades definidas na 4.1 estão contempladas nos requisitos. Também foi mantida a separação entre as funções da secretária e a consulta da agenda pelo veterinário, conforme definido na seção "Quem usa". A regra de prevenção de conflitos de horário foi registrada separadamente no RF08, complementando o processo de agendamento.
