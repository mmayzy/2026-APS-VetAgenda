# 4.2.1 Levantamento de Requisitos

## Como os requisitos foram levantados

Os requisitos do VetAgenda foram levantados a partir da análise da rotina de uma clínica veterinária e das necessidades apresentadas pela cliente Clarice, secretária da clínica.

Foi realizada uma conversa simulada com a cliente para entender quais informações precisam ser registradas, como são realizados os agendamentos e quais situações precisam ser controladas pelo sistema.

## Da fala à necessidade

| # | Fala | O que é | Necessidade por trás |
|---|---|---|---|
| F1 | "Preciso manter os dados dos tutores organizados para conseguir encontrar as informações quando necessário." — Clarice | necessidade | cadastrar e consultar os dados dos tutores |
| F2 | "Um tutor pode ter mais de um animal, então preciso conseguir relacionar cada animal ao seu tutor." — Clarice | necessidade | cadastrar animais e relacioná-los aos respectivos tutores |
| F3 | "Preciso ter os dados dos veterinários cadastrados para conseguir marcar as consultas." — Clarice | necessidade | cadastrar veterinários |
| F4 | "Quero conseguir marcar as consultas informando o animal, o veterinário, a data e o horário." — Clarice | necessidade | realizar o agendamento de consultas |
| F5 | "Não pode ter duas consultas para o mesmo veterinário no mesmo horário." — Clarice | necessidade | impedir conflitos de horários na agenda |
| F6 | "Quando uma consulta for cancelada, preciso que isso apareça na agenda." — Clarice | necessidade | permitir o cancelamento e atualizar a situação da consulta |
| F7 | "Às vezes o cliente precisa mudar o horário, então preciso conseguir reagendar." — Clarice | necessidade | permitir o reagendamento de consultas |
| F8 | "Preciso conseguir visualizar os horários e saber quais consultas estão marcadas." — Clarice | necessidade | consultar a agenda da clínica |

| # | História de usuário | Veio de |
|---|---|---|
| HU01 | Como **secretária**, quero **cadastrar um tutor**, para **manter os dados dos clientes organizados**. | F1 |
| HU02 | Como **secretária**, quero **cadastrar um animal e relacioná-lo ao seu tutor**, para **manter os dados dos animais organizados**. | F2 |
| HU03 | Como **secretária**, quero **cadastrar um veterinário**, para **poder relacioná-lo às consultas**. | F3 |
| HU04 | Como **secretária**, quero **agendar uma consulta**, para **organizar os atendimentos da clínica**. | F4 |
| HU05 | Como **secretária**, quero **consultar a agenda**, para **visualizar os horários e consultas marcadas**. | F8 |
| HU06 | Como **secretária**, quero **cancelar uma consulta**, para **manter a agenda atualizada**. | F6 |
| HU07 | Como **secretária**, quero **reagendar uma consulta**, para **alterar o horário quando necessário**. | F7 |

## Requisitos funcionais

| # | Nome | Requisito | Veio de |
|---|---|---|---|
| RF01 | Cadastrar tutor | O sistema deve permitir que a secretária cadastre um tutor. | HU01 |
| RF02 | Cadastrar animal | O sistema deve permitir que a secretária cadastre um animal e o relacione ao seu tutor. | HU02 |
| RF03 | Cadastrar veterinário | O sistema deve permitir que a secretária cadastre um veterinário. | HU03 |
| RF04 | Agendar consulta | O sistema deve permitir que a secretária agende uma consulta informando o animal, o veterinário, a data e o horário. | HU04 |
| RF05 | Consultar agenda | O sistema deve permitir que a secretária consulte as consultas e horários agendados. | HU05 |
| RF06 | Cancelar consulta | O sistema deve permitir que a secretária cancele uma consulta agendada. | HU06 |
| RF07 | Reagendar consulta | O sistema deve permitir que a secretária altere a data ou o horário de uma consulta. | HU07 |
| RF08 | Evitar conflito de horário | O sistema não deve permitir duas consultas para o mesmo veterinário no mesmo horário. | F5 |

## Requisitos não funcionais

| # | Categoria | Requisito | Veio de |
|---|---|---|---|
| RNF01 | Usabilidade | O sistema deve apresentar as informações de forma simples e organizada para facilitar o uso pela secretária. | necessidade da cliente |
| RNF02 | Acesso | O sistema deve permitir o acesso somente a usuários autorizados da clínica. | necessidade da clínica |
| RNF03 | Dispositivo | O sistema deve funcionar em navegador, sem necessidade de instalação de um programa específico. | características da 4.1 |

## Conferência com a 4.1

| Item do escopo (4.1) | Requisitos |
|---|---|
| O sistema permite cadastrar tutores. | RF01 |
| O sistema permite cadastrar animais. | RF02 |
| O sistema permite cadastrar veterinários. | RF03 |
| O sistema permite agendar consultas. | RF04 |
| O sistema permite consultar a agenda. | RF05 |
| O sistema permite cancelar consultas. | RF06 |
| O sistema permite reagendar consultas. | RF07 |
| O sistema evita conflitos de horários para o mesmo veterinário. | RF08 |

**Toda história tem requisito?** Sim. HU01 está relacionada ao RF01, HU02 ao RF02, HU03 ao RF03, HU04 ao RF04, HU05 ao RF05, HU06 ao RF06 e HU07 ao RF07.

**Todo requisito tem origem?** Sim. Os requisitos RF01 a RF07 vieram das histórias de usuário. O RF08 veio diretamente da necessidade identificada na fala F5 da cliente.

**O que a conferência mudou?** A confirmação com a cliente ajudou a detalhar melhor os requisitos do sistema, principalmente as informações necessárias para realizar um agendamento e a necessidade de impedir conflitos de horários para o mesmo veterinário.

## Confirmação com a cliente

Durante a confirmação, foram feitas as seguintes perguntas para Clarice:

**1. Quais informações precisam ser cadastradas sobre o tutor?**

Clarice: "Preciso do nome, telefone e CPF para conseguir identificar e entrar em contato com o tutor."

**2. Quais informações precisam ser cadastradas sobre o animal?**

Clarice: "Preciso do nome do animal, espécie, raça, idade e do tutor responsável."

**3. Um tutor pode ter mais de um animal?**

Clarice: "Sim. Um mesmo tutor pode ter vários animais cadastrados."

**4. Quais informações precisam ser cadastradas sobre o veterinário?**

Clarice: "Preciso do nome, número do CRMV e especialidade."

**5. O que precisa ser informado para marcar uma consulta?**

Clarice: "Preciso selecionar o animal, o veterinário, a data e o horário da consulta."

**6. Pode haver duas consultas para o mesmo veterinário no mesmo horário?**

Clarice: "Não. O sistema precisa impedir esse tipo de conflito."

**7. O que acontece quando uma consulta é cancelada?**

Clarice: "A consulta deve ficar como cancelada e o horário precisa ficar disponível novamente."

**8. É necessário poder mudar o horário de uma consulta?**

Clarice: "Sim. Preciso conseguir reagendar quando o tutor pedir uma mudança."

**9. O que você precisa visualizar na agenda?**

Clarice: "Preciso ver os horários, os animais, os veterinários e a situação de cada consulta."

**10. Quem vai utilizar o sistema?**

Clarice: "Inicialmente, a secretária será responsável por utilizar o sistema."
